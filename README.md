# Leafmark · 拾叶智能书签

Leafmark（拾叶）是一个可直接加载的 Chrome Manifest V3 扩展，无需构建、无需部署后台。沿用现有书签文件夹，提供智能归类、全库搜索和自定义大模型 API 配置。

## 安装

1. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 **`extension` 文件夹**（其中包含 `manifest.json`）。
3. 在浏览器工具栏的拼图菜单中固定「拾叶 · 智能书签」。
4. 打开想收藏的网页，点击拾叶，再点击「收藏 / 调整当前页」。

如果使用压缩包，请先解压，再选择解压后的 `extension` 文件夹。Chrome 127 及以上版本；运行插件不需要 Node.js。

### 1.2.3：闲置后的首次打开

工具栏快捷弹窗进一步改为纯静态 HTML：首次显示不加载任何 JavaScript 或外链样式，不查询书签状态，不唤醒后台，也不等待模型或本机配置。按钮统一显示「收藏 / 调整当前页」，点击后在同一弹窗进入归类页面，识别已收藏状态并给出建议；原标题、网址和书签 ID 的保留规则不变。管理页与 Antigravity 的主样式保持不变。

归类页面的当前页状态直接调用 Chrome API，不经过后台消息。原生收藏事件直接打开归类页面；手动打开工具栏仍进入静态快捷页。

`scripts/cold-popup-test.mjs` 使用独立配置加载实际安装的 Chrome，通过浏览器调试接口触发真实工具栏动作。触发前关闭扩展页面并停止后台，验证窗口创建、内容就绪与后台未被唤醒；可设置 `COLD_WORKER_DELAY_MS=6000` 在测试副本中注入启动延迟，验证普通快捷页不依赖后台。它不接触日常 Chrome 配置，计时也不代表日常配置下的点击延迟。录屏中的长时间不出窗尚需更新后在实际浏览器复测。

### 1.2.2：轻量工具栏弹窗（此前版本）

沿用现有绿色主题、渐变图标、圆角和间距风格。工具栏弹窗只显示当前页收藏/调整分类按钮、已有收藏的目录，以及书签空间、批量整理、设置入口，不展示书签列表或全文搜索框。

普通打开不请求整库、不读取正文索引或整理记录、不迁移索引、不加载完整管理页代码与样式，只异步查询当前页收藏状态。点击收藏/调整分类或收到原生收藏的自动建议时，才加载原有归类面板及所需目录。浏览、搜索、待归类和批量整理集中在完整书签空间。状态查询失败时可重试，管理入口仍然可用。主样式文件保留 Antigravity 的优化。

### 1.2.1：弹窗启动响应（此前版本）

工具栏弹窗先显示固定尺寸的加载界面和管理页快捷入口，再异步读取书签列表。列表只读取轻量摘要，输入搜索词后才分批读取正文；已有正文索引首次使用时，在界面显示后分批生成摘要，不删除或重新采集原索引。批量整理界面按需加载，整理记录变化不再触发普通弹窗反复刷新。配置导入不阻塞弹窗列表；后台响应较慢或失败时显示加载状态和重试入口。

更新后，在 `chrome://extensions` 中对已加载本项目 `extension` 目录的「拾叶」点击一次重新加载，再点击工具栏图标即可。配置及书签保留。

### 1.2.0：批量整理书签

管理页左侧新增「批量整理」，工具栏弹窗的「批量整理书签」入口也可直接进入。沿用现有 DeepSeek / 自定义 API 配置。

1. 选择全部书签或某个目录（包含子目录），选择大模型或本地规则。
2. 默认只推荐已有目录。需要重新建立分类体系时，可勾选「允许新建分类目录」，并指定新分类的保存目录；支持最多三级分类。
3. 点击「开始分析」。每批最多 20 条，显示分析进度、建议来源和回退提示。分析阶段只生成建议，不移动书签或创建文件夹。
4. 在预览中对照「当前位置 → 建议位置」，可筛选、修改目标目录、新分类路径、忽略单条建议，或勾选应用。筛选不会自动取消其他已勾选项，请以「应用选中」数量为准。
5. 应用时复用同一父目录下名称相同（忽略大小写）的目录，必要时才创建新目录；保留书签 ID、原标题和网址。跳过已被其他操作编辑/移动的书签，并显示原因。
6. 「撤销已应用的移动」按相反顺序恢复原目录和顺序；如果某条书签后来被其他操作移动，则跳过，避免覆盖后续改动。新建的分类目录会保留。

分析与移动记录保存于本机。可以暂停、继续；关闭页面后会完成当前分析批次或当前移动，剩余操作留待重新打开后继续。浏览器后台中断时，可根据持久化记录与真实书签位置恢复状态。重新分析会替换当前建议，但保留已应用移动的撤销记录。不要在多个页面同时处理同一整理任务。

大模型批量分析仅发送所选范围的标题、网址、原目录及最多 100 个候选目录；启用新分类时还发送此前批次建议的分类名称以便复用。不会发送页面正文或密钥以外的配置。API 失败、漏项或非法返回会明确显示本地回退，未找到充分分类依据时保留当前位置。

### BookmarkAI 的参考逻辑与本项目实现

已只读检查 `D:\AIProjects\workspace\extension\BookmarkAI` 的 `background.js` / `options.js`：

- `organizeBookmarks` 收集整库书签标题、网址和路径，`classifyBookmarksWithAI` 每 20 条调用一次模型；`createClassificationPrompt` 请求 2–3 级分类。
- `parseCategoryResults` 把模型的文本结果解析为书签 ID 与分类路径，再将建议保存在本地；`options.js` 展示分组预览，提供单条与批量确认。
- `moveBookmarkToCategory` 从书签栏逐级查找或新建目录，再移动已有书签。

拾叶参考上述流程独立实现批量整理，使用严格 JSON / 真实目录 ID 校验、动态根目录 ID、默认沿用已有目录、明确的新目录开关、可中断批次和移动日志。没有照搬原项目固定书签栏 ID、相似名称目录自动合并、把 API Key 写入日志等实现。原项目的重复链接删除、失效检测和空目录清理是独立功能，本次新增的是 AI 批量分类整理。

### 1.1.1 更新

弹窗会检查当前页是否已收藏：未收藏显示「收藏当前页」；已收藏显示「已收藏 · 调整分类」及所在目录。调整分类操作移动原书签，保留 ID、标题和网址，不重复创建。书签删除或页面网址改变后会更新按钮状态；已有页面可在调整分类面板中点击「更新当前页正文索引」，单独刷新本地可搜索正文。

### 1.1 更新

点击当前页的空心星标或按 Ctrl+D 新增书签，会立即自动弹出拾叶建议面板：先给出本地推荐，再在同一面板更新大模型结果。点击「确认归类」会直接移动这条真实 Chrome 书签；手动选择的目录不会被稍后返回的模型结果覆盖。也支持收藏本插件管理页等内部页面，只读取书签元数据。

图中的 Chrome 原生收藏面板属于浏览器界面，扩展不能往其中插入建议或控制其下拉框。自动打开拾叶面板时会替换当前原生气泡，先让原生编辑完成，再应用推荐目录；重新打开原生面板可查看保存后的目录。点击已收藏的实心星标只打开 Chrome 原生编辑，不产生新建书签事件，不能被本插件自动识别。同步、导入或后台创建的非当前页书签不会抢占焦点。

## 已实现

- **收藏推荐**：读取当前页标题、网址和简介，推荐 1–3 个已有目录；可手动选择任意可写目录，确认后保存。不会创建额外分类目录。
- **原生收藏识别**：Chrome 星标或 Ctrl+D 新建当前页书签后，自动弹出具体书签的归类建议；若浏览器不允许打开工具栏弹窗，则使用独立扩展窗口。工具栏角标和「待归类」仍可查看未处理建议，不能自动呈现时可用通知兜底。
- **全库搜索**：搜索所有书签标题、网址、完整目录路径、已保存的简介和正文；空格分隔的多个词需同时匹配。即使从某个文件夹进入，输入关键词后也会搜索全部文件夹。
- **正文索引**：通过插件收藏网页时，保存当时的页面正文（最多 80,000 字符）供本地搜索。旧书签和原生收藏默认只有标题、网址和目录；在原网页打开插件，点击「已收藏 · 调整分类」后使用「更新当前页正文索引」可建立或刷新索引。没有后台自动爬取全部历史网页。
- **API 配置**：填写基础地址、API Key 和模型名称，支持测试连接、保存配置、保留或移除已存密钥；使用 OpenAI Chat Completions 兼容协议。原生 Anthropic Messages、Gemini 原生协议需通过兼容网关接入。
- **本地回退**：没有配置 API、权限被撤销、网络超时或模型返回非法目录时，使用本地目录关键词和同域名历史进行推荐。错误会显示，不会伪装成模型成功响应。
- **书签空间**：文件夹导航、近 30 天收藏、统计、卡片和列表视图；监听真实 Chrome 书签变化。重复收藏同一网址（忽略片段和末尾斜杠）会更新已有书签的位置与索引。
- **偏好设置**：可分别关闭原生收藏推荐、系统通知和新的正文索引，或单独清除本地正文索引。

## 配置 API

从插件右上角设置按钮进入「模型与偏好设置」，填写服务商提供的信息：

| 字段 | 说明 |
| --- | --- |
| API 基础地址 | 例如 `https://your-provider.example/v1`；不要填写结尾 `/chat/completions`。插件会自动追加该路径。 |
| API Key | 服务商颁发的密钥；本地免密服务可留空。已保存密钥时，留空会保留原值。 |
| 模型名称 | 填写该服务实际支持的模型 ID。 |

点击「测试连接」或「保存配置」时，Chrome 会请求访问该 API 站点。拒绝授权则不会保存配置。测试成功后仍需点击「保存配置」才能应用当前修改。本地服务支持 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`；远程服务要求 HTTPS。

插件 POST 到 `{基础地址}/chat/completions`，使用 `Authorization: Bearer {API Key}`。请求包含 `model`、`messages`、`temperature` 和 `max_tokens`，预期响应为 `choices[0].message.content`。单次请求 22 秒超时。服务商可能收取调用费用。

默认服务为 `https://api.deepseek.com`，模型为 `deepseek-v4-pro`，使用非思考模式以适应短时分类请求。模型名称和请求参数依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

当前本机开发目录另有被 Git 忽略的 `extension/local-settings.json` 私有配置。重新加载此目录后，插件会一次性导入该配置到 `chrome.storage.local`，导入后以设置页中的修改为准。发布压缩包通过 `npm run package` 的公开文件白名单打包，明确排除私有文件和密钥；从压缩包安装时需要自行填写 API Key。不要手工把整个开发目录压缩后分发。

## 数据和权限

- 书签直接保存在 Chrome 原生书签树中，Chrome 自身的书签同步行为照常生效。
- API Key 仅保存在 `chrome.storage.local`，不使用 `storage.sync`，不会随插件同步。扩展存储不是系统密码保险库；有本机配置文件访问权限的人可能读取其中数据。
- 启用 API 推荐后，页面标题、网址、简介和最多 60 个候选目录 ID / 完整路径会发送给所配置的服务。网页正文不发送给模型。收藏 / 推荐操作及已启用的原生收藏监听可能触发请求。
- 搜索在本地执行，不向 API 发送搜索词。正文和简介保存在本机，可在设置中清除；卸载插件会移除扩展本地数据，原生书签保留。
- `bookmarks`：读取和保存书签、移动目录；不提供删除书签功能。
- `storage`、`unlimitedStorage`：保存配置、待确认建议和正文索引，避免少量长文很快达到默认索引空间上限。
- `activeTab`、`scripting`：用户点击插件时读取当前页；没有常驻的全站内容脚本。
- `notifications`：显示新收藏归类提醒；系统关闭通知时仍可查看工具栏角标。
- DeepSeek 官方 API 具有单独的固定站点权限；其他自定义 API 域名仍使用 `optional_host_permissions`，由用户明确操作时按站点授权，不默认获得全部网站访问权限。
- `tabs`：只用来核对新增书签是否对应当前活动页面，避免同步或后台创建书签时自动弹窗；这不授予所有网站的页面正文读取权限。

Chrome 内部页面、商店等受限网页不支持正文读取，插件会提示原因；书签中的特殊协议链接请在 Chrome 原生书签管理器打开。受管理员控制的目录不会作为保存目标；批量导入书签期间不会逐条触发模型推荐。首次安装不会扫描并发送历史书签到模型。

## 开发验证

验证脚本需要 Node.js 20.11+（推荐 24）；当前系统默认的 Node 14 不支持这些测试工具，但不影响 Chrome 加载插件。

```powershell
npm test
npm run check
node scripts/preview.mjs
```

界面预览地址为 `http://127.0.0.1:4317`，使用明确标记的示例数据，不会读取真实书签，不能测试真实 API。加载插件后自动使用 Chrome API，不会注入示例书签。

`scripts/browser-test.mjs` 使用 Playwright 启动独立的临时 Chromium 配置，加载真实 MV3 扩展，验证书签读写、全文 / 组合搜索、重新归类、偏好保存、原生收藏建议、保留原目录和弹窗尺寸。需要可加载扩展的 Chromium 与 Playwright，可通过 `PLAYWRIGHT_MODULE_PATH` 和 `BROWSER_PATH` 指定安装路径。测试不会接触日常浏览器配置。

`scripts/popup-startup-test.mjs` 在隔离配置中建立 165 条书签、每条 80,000 字符的旧正文索引及较大的整理记录。禁止整棵书签树读取，验证快捷弹窗没有脚本、外链样式、后台消息、正文读取或整库加载，以及实际工具栏弹窗目标创建；最后从真实管理入口进入完整管理页验证正文搜索。报告保存在 `artifacts/popup-startup-result.json`；测试中的计时不代表日常 Chrome 点击延迟，用户实际配置仍需重新加载后验收。

当前已完成自动化逻辑测试、独立 Chromium 中的真实扩展验证，以及 DeepSeek V4 Pro 实际连接测试。自动打开扩展目标、打开具体建议、实时更新模型推荐、保留手动选择和移动真实书签均已验证。批量整理使用 41 条隔离的真实 Chrome 测试书签和模拟模型响应，验证分批、暂停/继续、预览不移动、筛选勾选、应用、新建/复用三级目录、重载持久化和完整撤销顺序；另用 5 条公开示例完成真实 DeepSeek 批量返回校验。未分析或整理日常浏览器的实际书签库。日常 Chrome 的原生气泡显示、activeTab 正文读取和 Windows 通知仍需手动验收。
